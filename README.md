# 雪场出入口营运台

把“每半小时放号前判断在场人数 → 定入口/团体引导 → 核对容量与终端承诺 →
新一轮接报后复盘”的流程做成可往复使用的 Python 项目。纯 Python 3.11 标准库，
无第三方依赖。原始资料与口径见 [data/README.md](data/README.md)。

## 快速开始

```sh
# 原有来源概要工具
python3 scripts/inspect_sources.py

# 营运台：主经营日 2026-02-17 的完整文字报告
python3 -m opsdesk report
python3 scripts/desk.py report           # 等价薄封装

# 只看某个 as-of 轮次（known_at / posted <= 3）
python3 -m opsdesk round --asof 3

# 历史独立收尾点验回测（覆盖率 + 可能误放行分区）
python3 -m opsdesk backtest

# 完整 JSON 台账（可接前端/报表），并落盘样例
python3 -m opsdesk report --json --out reports/desk-2026-02-17.json

# 测试（含原始数据契约测试 + 营运台口径测试）
python3 -m unittest discover -s tests
```

也可把整套新一轮 JSON 放到另一个目录后用 `--data /path/to/data` 重跑，
或在代码里：

```python
from opsdesk import OperationsDesk, load_workspace, infer_day

desk = OperationsDesk("data", day="2026-02-17")
print(desk.round_report(asof=4))     # 某一轮
print(desk.response_options())      # 入口分流 vs 暂缓发售
print(desk.backtest())              # 历史回测
```

## 时段与推断口径

- 每经营日 8:00 起按半小时编号 `W0..W8`；`N(z,w)` 表示窗口 `w` **开始时**
  A/B/C 区人数，`f(e,w)` 表示有向连接 `e` 在窗口 `w` 内的穿越人数。
- 闸机为同 `counter_epoch` 累计计数，已用全部 **120** 条人工截面记录验证：
  `f(e,w) = C(e,w) - C(e,w-1)`（110 条被闸机精确钉死并落在人工区间内，
  10 条缺脉冲场景区间相容，**0 冲突**）。
- 推断引擎（`opsdesk/inference.py` + `constraints.py`）把下列关系统一成线性
  区间约束并传播到不动点，输出的每个上界都不会低估仍可能成立的真实人数：
  - 区域平衡 `N(z,w)=N(z,0)+G(z)+Σ sign·P(e,w-1)`，其中 `P` 是累计穿越量、
    `G(z)` 是无前置读数的 W0 净流（由 w2 等区内点验收紧）；
  - 闸机相邻累计点差分；缺脉冲时只成立跨窗总量
    `C(q)-C(p)=Σ_{w=p+1..q} f(e,w)`，**绝不把缺的窗口设 0**；
  - 人工截面上下界、区内点验上下界（与非负相交）；
  - 通道容量与 closures 封闭方向（封闭即 `f=0`）。
- **独立收尾点验不进入推断**，只用于回测核对（data/README 口径）。

### 几笔账怎么入（`accounting_rules`）

| 事项 | 入账方式 |
| --- | --- |
| 边界外 O 进出 | E1(O→A)、E2(O→C) 记首入区流入；CO(C→O) 记 C 流出。O 不设容量，残差留 O 侧 |
| 同一人折返（AB 后再 BA） | 按穿越次数分方向各记一次，不轧差；全天净额可抵消，窗内人数不会 |
| 跨区移动（A→B→C） | AB、BC 各计一次，且 AB 同时是 A 流出与 B 流入，两侧引用同一变量，天然对得上 |
| 封道口排队未穿越 | 无脉冲不移动分区，仍计原区；只在承诺口径预留“未来流入” |
| 已扫码未走完通道 | 仍计出发区，不算离场，同时作为刚性未来流入预留到达区 |
| 缺脉冲 | 给跨窗总量与区间，不设零 |
| 恢复后补传 | 同 key 以最后 `known_at` 读数为准，差额追溯到 `observe_time`，不在接收窗制造跳变 |

## 2026-02-17 主场景是怎么对上的

- 三区开场点验 A20/B14/C17。全日资料重建的 `N8 = A[47,49] / B[1,2] / C[16,18]`，
  独立收尾点验 **A48 / B1 / C17 全部落在区间内**；中值 A=48 恰好触硬上限。
- **放号前第 3 轮**：BA 的 obs3 读数延迟到 `known_at=4`，asof3 时 B→A 当窗
  最多 16 人未知，`N(A,W4)=[32,50]`，上界已超过硬上限 48 —— 此时 **E1 数据
  不足以支持继续发票，保守可放 0**；首要限制方向就是 **BA（延迟回传）**。
- **第 4 轮脉冲到达后**：`N(A,W4)=[35,37]`、核定中值 36。运营上限
  `48-保留7=41`，`41-36=5`，恰好解释补发版本 **L1/2 quota=5**；严格按点验
  上界 37 的保守可放为 **4**，硬上限口径可放 **11**。E2→C 容量充足，受入口
  通道上限约束可放 **18**。
- **单向不借用**：C1 令 AB 在 W3–W5 封闭，C2 显示 BA 仍开放（临时单向 B→A）。
  AB 封闭期间 A 没有可确认的流出，W4 流出下界为 0，不能把 BA 或 B 区空位
  挪作 A 的疏散能力。
- **下游饱和共享先离开名额**：E1 的下游 A 在 W5 `[39,41]` 贴近运营上限且 AB
  封闭，可先行离开名额为 0，E1 只能按 A 自身头额放号；E2 下游 C 无饱和点，
  CO 当窗可确认流出 7。
- **团体**：G1（9 人，已签到在途）必须继续接待且不改口，硬口径 11 可容纳；
  G2（11，已出票）可改引 E2 9 人、余 2 人留 E1，**集合时间 W4 保留不变**；
  G3（15，已付待发）、G4（10，可协商）走协商改场次/暂缓。
- **终端版本承诺**（出票扣到 `(tranche, version)`）：
  - L1/1(T-A,14)：售 7；J5 归还 5，J6 回执订正为 4 → 确认回收 4、未回收 **3**，
    总承诺 `7+3=10`（第 6 轮曾为未回收 2，第 7 轮订正又挂回 1，正是新一轮
    接报改变上一轮结论的来源）；
  - L1/2(quota5, 替换 L1/1)：J4 **接收失败** → 停发 T-A 下一批，终端敞口 0，
    但中央当前版仍为 5；
  - L2/1(T-B,10)：售 6、未回收 **4**，承诺 10；
  - L3/1(T-C,13,W5)：**无任何接收回执**，不能假定没出票，整版 13 保守计为敞口。
- **W4 缺口与选择**：E1 刚性团体 20 + 终端承诺 10 = 30 对硬槽位 11（缺口 19）；
  E2 承诺 10 对 18（余 8）。合计保守承诺 40 对硬槽位 29，总缺口 11。
  - *入口分流*：把 G2 的 9 人引到 E2，启用 E2 的 8 个空余硬槽（仍不足部分
    与散客缺口并列），集合时间不变；
  - *暂缓发售*：停 E1 新散客票、停 T-A 下一批、催回 7 个未回收终端余量与
    L3 回执，G3/G4 协商场次；在途 G1 与已出票份额始终保留。
- **晚到计数追踪**：known_at=6 的 A 区内点验 `[39,41]` 把 `N(A,W6)` 推到
  `[44,46]`，越过运营上限 41 → 立即停 E1 后续新票；仍有效票 = L1/v1 已售 7、
  L2/v1 已售 6 及 G1/G2；各终端待回收 3/4/13 见 `stop_trace`。
- **复盘**：`audit` 逐轮（3→4→6→7→9）列出新闸机读数（含 BA 延迟脉冲、AB
  补传）、晚到点验、终端事件如何改变区间，并归入流量推断 / 晚到点验 /
  终端确认 / 封闭绕行四类；AB 补传值相同，第 7→9 轮人数区间 0 变动。

## 历史回测结论

`python -m opsdesk backtest`：

- 独立收尾点验上界覆盖 **36/36 = 100%**，中值平均绝对误差 0.25 人；
- 日内点验区间相容 **72/72 = 100%**；
- 16 个经营日中，独立点验确认的实质越限/可能误放行分区只有
  **2026-02-17 A 区（收尾 48 = 硬上限，且 > 运营上限 41）**；
- W4/asof3 的流程性风险几乎都指向同一个缺测方向 **BA 延迟回传**，其次是
  缺 w0 开场锚点导致的开场净流无界——报告把“可能误放行 / 不能自证安全 /
  缺开场锚点”分成三张清单，避免把信息不足误报成已经超员。

> 反例对照：若把缺脉冲相邻累计差缺失的窗口直接填 0，跨窗总量会被整段漏掉，
> B 区这类“大穿流、小滞留”的分区会被算成负数并系统性低估收尾人数
> （12 个有点验的 B 区样本全部低估，最多差 16 人）。

## 代码结构

```
opsdesk/
  timegrid.py     半小时窗口与当地时钟
  bounds.py       整数闭区间与运算
  io.py           data/*.json 读取 / Workspace
  network.py      O/A/B/C 有向连接、路径
  closures.py     封闭/单向状态（[start,end)）
  sensors.py      闸机累计台账、as-of 视图、补传最后有效读数
  constraints.py  线性区间约束传播器（标准库）
  inference.py    人数/流量推断、限制方向、人工对账
  capacity.py     分区上限+通道容量包络、下游饱和瓶颈
  terminals.py    限额版本、终端事件轮次快照、未回收承诺
  callbacks.py    可往复登记的版本化售票/到场回传
  groups.py       团体分级、改口保留集合时间的安置器
  backtest.py     独立收尾点验覆盖与误放行清单
  audit.py        轮次差异与三类误差归因
  desk.py         OperationsDesk 门面与完整报告
  cli.py/__main__.py
tests/test_opsdesk.py  21 条营运台口径测试；tests/test_data_contract.py 原始契约测试
reports/               生成的 JSON 报告样例
```
